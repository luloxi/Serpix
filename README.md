# Serpix

ERP personal y extensible para relaciones comerciales, tareas y finanzas.

## Stack

- Next.js App Router + React
- Cloudflare Workers con `@opennextjs/cloudflare`
- Cloudflare D1 (SQLite)
- Better Auth + Google OAuth
- GitHub como fuente del código y despliegues

## Acceso

El registro se realiza con Google. Las cuentas nuevas quedan en estado `pending` y no pueden acceder a los módulos hasta que un administrador las apruebe.

La cuenta administradora inicial es `lucianoolivabianco@gmail.com`. Su rol se asigna automáticamente en el primer inicio de sesión. Los roles y estados de aprobación son campos administrados por el servidor.

## Cloudflare

El Worker se llama `serpix`, usa la base D1 `serpix-production` y está previsto para `erp.lulox.com.ar`.

Configurar como secrets del Worker (nunca en Git):
- `BETTER_AUTH_SECRET`: valor aleatorio criptográficamente seguro de al menos 32 caracteres.
- `GOOGLE_CLIENT_ID`: ID del cliente OAuth de Google.
- `GOOGLE_CLIENT_SECRET`: secreto del cliente OAuth de Google.
- `PORTFOLIO_INBOUND_SECRET`: secreto compartido con el portfolio (`steal-this-portfolio`, donde se llama `SERPIX_INBOUND_SECRET`). El portfolio lo manda en el header `x-serpix-secret` a `POST /api/inbound/portfolio`.
- `VAPID_PRIVATE_KEY`: clave privada VAPID (base64url) para las notificaciones push. La pública es la variable `VAPID_PUBLIC_KEY` de `wrangler.jsonc`.

El callback OAuth es `https://erp.lulox.com.ar/api/auth/callback/google`.

```

```

```bash
npx wrangler d1 migrations apply serpix-production --remote
```

Para desplegar:

```bash
npm run deploy
```

## Estado funcional

- Google OAuth y sesiones: configurados en código; requieren los secrets y el despliegue.
- Aprobación de usuarios: flujo inicial, estados y endpoints administrativos implementados.
- CRM, agenda (tareas, eventos y notas) y finanzas: esquema persistente y operaciones CRUD (crear, editar, eliminar) implementados en `/dashboard`, aislados por usuario.
- Logo e íconos: ouroboros grueso rosa → violeta → celeste con signo $ amarillo sobre negro. El original está en `brand/serpix-logo-master.v5.png` (el anterior, fino, sigue en `brand/serpix-logo-master.jpg`); `python3 scripts/make-icons.py` genera los PNG/ICO livianos de `public/icons` (favicon, Apple Touch, PWA 192/512, logo de la barra lateral y el anillo del botón + `fab-ring.v5.png`). Los nombres llevan versión (`.v5`) para evitar cachés viejas; el manifiesto es `manifest-v5.webmanifest`.
- Almacén canónico del logo: bucket R2 `serpix-assets` (plan gratuito), publicado en https://assets.lulox.com.ar/logo/v1/ (versión fina) y https://assets.lulox.com.ar/logo/v5/ (versión gruesa vigente: `serpix-logo-master.v5.png`, `serpix-32.v5.png`, `serpix-48.v5.png`, `apple-touch-icon-180.v5.png`, `icon-192.v5.png`, `icon-512.v5.png`, `logo-128.v5.png`, `favicon.v5.ico`, `fab-ring.v5.png`). Archivos de v1: (`serpix-logo-master.jpg`, `serpix-32.png`, `serpix-48.png`, `apple-touch-icon-180.png`, `icon-192.png`, `icon-512.png`, `logo-128.png`, `favicon.ico`; `Cache-Control: public, max-age=31536000, immutable`). La app sigue sirviendo favicon, Apple Touch, manifiesto y logo de la interfaz desde su propio origen (`public/icons`), porque los navegadores y la instalación de la PWA manejan mal los íconos de otro origen.
- No se incluye información ficticia ni datos de demostración.
- Navegación: Resumen · Contactos · Agenda · Finanzas + avatar de perfil (tema oscuro, administración, cerrar sesión).
- Agregar nuevo: el botón + abre una hoja inferior con 8 acciones (Contacto, Tarea, Evento, Nota, Factura, Gasto, Temporizador y Cuenta). Factura abre el editor de facturas (ver "Facturas y presupuestos"); Gasto abre el formulario de movimiento con el tipo egreso preseleccionado. Sin cuentas, se abre el alta de cuenta y un aviso. Temporizador solo dispara el evento `serpix:timer-start`. La hoja se cierra con el fondo, con Escape o al elegir una acción, y atrapa el foco.
- CRM: contactos con relación (cliente, cliente potencial, socio, socio potencial, proveedor, prospecto), filtro por relación, ficha expandible con tareas, eventos y notas vinculadas. Teléfono con `+54` sugerido y editable; X, Instagram, Telegram, WhatsApp y LinkedIn opcionales (aceptan `@usuario` o enlace); notas libres.
- Resumen: primera pantalla compacta (saludo, fecha corta, 4 indicadores con ícono y tooltip clickeables, próximas tareas con casilla para completarlas).
- Relaciones: un contacto puede ser a la vez cliente, socio y/o proveedor, cada uno potencial o confirmado (columna `contacts.relations`, JSON; si es NULL se deriva del `role` viejo sin modificar filas: client/partner/supplier → confirmado, client_potential/partner_potential → potencial, `potential` ("prospecto") → sin relación). Al guardar se escribe `relations` y se mantiene `role` coherente. Filtros por relación y estado en Contactos.
- Foto de contacto: iniciales por defecto; se puede elegir la foto de X, Telegram, GitHub, LinkedIn o del email (Gravatar por SHA-256), o subir una propia. Todas se descargan una vez, se recortan a 256 px y se guardan como WebP (unos KB) en D1 (`contacts.avatar_data`, columnas aditivas `avatar_data`, `avatar_source`, `github_url`) y se sirven desde `/api/avatar/<id>` solo al dueño. Fuentes sin API key: unavatar.io (X, Telegram, GitHub, LinkedIn; plan gratuito ~25 consultas/día por IP) y Gravatar; Instagram no ofrece foto sin pago, por eso no se ofrece.
- Foto automática: si un contacto no tiene foto elegida/subida, al abrir su ficha (o al guardarlo) el navegador prueba en orden GitHub, X, Telegram, LinkedIn y Gravatar del email, toma la primera imagen válida y la guarda (`avatar_source = auto:<red>`). Nunca pisa una foto elegida o subida. Si ninguna red tiene foto, guarda el intento (`avatar_tried_at/key`) y no vuelve a probar hasta que cambien las redes o pasen 7 días; la lista nunca consulta servicios externos. unavatar.io devuelve una silueta SVG (200) cuando no puede leer un perfil de LinkedIn: se descarta (no es foto). Instagram queda fuera (403 de pago en unavatar; la API web exige login).
- Foto de WhatsApp: con un teléfono cargado, Serpix busca la foto pública de WhatsApp de ese número (unavatar.io, sin cuenta ni API key; ni tu WhatsApp ni servicios pagos) y se suma a las fuentes (chip WhatsApp y orden automático: GitHub, X, Telegram, LinkedIn, WhatsApp, email). El teléfono se normaliza a formato internacional (`lib/avatar-client.ts` `waNumber`, p. ej. +54 11 5555-1234 → 5491155551234). Sin foto pública unavatar devuelve una silueta genérica: se reconoce por su hash y se descarta. Se manda el número a unavatar.io (límite ~25 consultas/día por IP, compartido con las otras fuentes). Junto al teléfono hay un botón que abre `wa.me/<número>`.
- Sugerir perfiles: NO se pudo sugerir automáticamente (ningún buscador gratis permite consultas desde un servidor: DuckDuckGo pide captcha o da 522, Brave 429, Bing devuelve resultados sin relación). En su lugar, junto a LinkedIn e Instagram hay un botón de lupa que abre la búsqueda por nombre (+ empresa en LinkedIn) en otra pestaña para elegir el perfil y pegarlo.
- Agenda: pestañas General (Atrasadas/Hoy/Próximo), Calendario (mes con puntos por tipo) y Lista (filtro por tipo). Tareas en checklist con fecha y contacto; eventos; notas en Markdown con lectura y edición a pantalla completa y vista previa.
- Próximo (Agenda → General): ordenado por fecha; "Vencidas" en rojo arriba, un encabezado de mes una sola vez ("Octubre"; con año si no es el actual, sticky) y por día "Hoy · Vie 30", "Mañana · Sáb 31", "Mar 3" sin repetir el mes; hora a la derecha, ícono por tipo con tooltip, "Sin fecha" al final. "Hoy" es el día de America/Buenos_Aires.
- Agenda con pasado: General y Lista son una sola línea de tiempo con el pasado, hoy y lo que viene (mes una vez + día, color por mes). Al abrir queda posicionada en "Hoy" (sin animación, contando los encabezados sticky); arriba está lo anterior (se cargan de a un mes al llegar al tope, sin saltos de scroll) y abajo lo siguiente. Las pendientes vencidas van en un bloque rojo "Vencidas" justo arriba de Hoy (más una pastilla "N vencidas" que lleva a ellas cuando no se ven); lo hecho del pasado se ve atenuado en su día. Un botón "Hoy" (con flecha hacia donde está hoy) aparece al alejarte y vuelve al día actual. Calendario: abre en el mes actual con hoy seleccionado, flechas o swipe para otros meses y "Hoy" para volver. Sin fecha queda al final. Resumen no cambia.
- Colores de marca: `app/brand.css` define los 4 tonos (rosa #fe4aab, celeste #39c5ff, amarillo patito #f6cd35 y el violeta #ab96ff, punto medio exacto entre rosa y celeste en OKLCH con el croma ajustado al gamut sRGB) con sus variantes suaves y de texto legible (tokens `--brand-*`), y se carga después de `globals.css`. Estados seleccionados, botón +, bordes y foco usan solo esos tonos. Colores por mes: `lib/palette.ts` rota rosa, celeste, amarillo y violeta según el mes (siempre el mismo para el mismo mes) y se aplica a encabezados de la agenda, el calendario, los movimientos y las solicitudes.
- Finanzas: los totales de ingresos y gastos son agregados SQL sin límite ("Ver más" pagina la lista de movimientos de a 250), el saldo inicial de la cuenta se puede editar y se guarda, y los datos se refrescan al enfocar la ventana, al volver a la pestaña y después de cada cambio (sin sondeo cada 10 s).
- Solicitudes del portfolio: el formulario de `lulox.com.ar` (/contratar) sigue mandando el mail y además reenvía la solicitud a `POST /api/inbound/portfolio` por Service Binding (tabla `inquiries`; secreto en `x-serpix-secret`, 401 sin él; máx. 12 KB, 5 por hora por mail y 30 cada 10 min). Se ve en **Contactos → Solicitudes** (con contador sin leer en el menú, en el ícono bandeja de Resumen y en la pestaña): leída/no leída, archivar, responder por mail (`mailto:`) y convertir en contacto (crea uno nuevo como cliente potencial; si ya hay un contacto con ese mail solo se vincula, sin modificarlo).
- Notificaciones push: Web Push con VAPID implementado sobre WebCrypto (`lib/webpush.ts`, sin dependencias; `npm test`). Se activan por dispositivo en Perfil → Notificaciones (tabla `push_subscriptions`). Al entrar una solicitud el Worker avisa a todos tus dispositivos; tocar el aviso abre la solicitud. En iPhone hay que instalar Serpix en la pantalla de inicio primero.
- Temporizador y tiempo registrado: hoja con `HH:MM:SS` (Pausa/Reanudar y Detener), pastilla flotante al minimizar y pantalla para guardar el registro (inicio y fin en hora de Buenos Aires, ±5 min, redondeo a 15 min, tarea, facturable en ARS). El estado vive en D1 (`timer_state`, `time_entries`) y se cachea en el navegador para el primer dibujo. En Agenda (General y Lista) cada tarea muestra el tiempo acumulado; en Finanzas, el panel "Tiempo registrado".
- Facturas y presupuestos (comprobantes internos, **no son facturas fiscales de ARCA**; el PDF lo aclara): tablas `documents`, `document_items` y `document_time_entries` (migración `0010_documents.sql`, aditiva). Tipo presupuesto o factura con numeración correlativa por tipo y usuario (`P-0001`, `F-0001`), cliente (contacto), fecha, vencimiento, moneda ARS/USD, ítems (descripción, cantidad, precio) y notas. Estados: borrador, enviada, cobrada, anulada; **vencida** no se guarda, se deriva (factura enviada, sin cobrar y con vencimiento anterior a hoy en hora de Buenos Aires). "Marcar enviada" solo cambia el estado: Serpix no manda mails. Presupuesto → factura con un botón (copia ítems y cliente, vence en 15 días; idempotente: un presupuesto genera una sola factura). "Cobrar" elige una cuenta de la misma moneda y crea el ingreso en Finanzas (categoría "Factura") una sola vez: el vínculo `documents.transaction_id` es único, repetir la acción no duplica y la factura cobrada queda cerrada. "Horas" importa como ítems las horas facturables del cliente (tareas del contacto, sin comprobante todavía) y las marca para no facturarlas dos veces. Solo se borran borradores; el resto se anula. Se usa desde Finanzas (panel "Facturas y presupuestos") y desde el + → Factura (`app/documents.tsx`, API en `app/api/documents`, lógica en `lib/documents.ts`).
- PDF y compartir: el PDF se genera en el navegador, sin servicios pagos ni servidor (`lib/pdf.ts` es un escritor de PDF mínimo sin dependencias; `lib/document-pdf.ts` es el diseño con el logo v5 y la paleta; `app/document-pdf.ts` mide el texto con canvas). "PDF" lo descarga; "Compartir" usa Web Share con el archivo si el dispositivo lo permite y, si no, descarga el PDF y abre WhatsApp (`wa.me`) con un mensaje corto para adjuntarlo.
- Cobros atrasados: las facturas vencidas se ven con fondo y etiqueta rojos en la lista y en un panel "Cobros atrasados" de Resumen. Un cron diario gratuito de Cloudflare (`worker.ts`, 12:00 UTC = 09:00 Buenos Aires) manda UNA notificación push por usuario con las facturas que recién vencieron (mismo mecanismo VAPID que las solicitudes; `lib/documents-push.ts`) y las marca (`overdue_notified_on`) para no repetirla; si el envío falla se reintenta al día siguiente. `worker.ts` envuelve el handler de OpenNext y es la entrada del Worker (`main` en `wrangler.jsonc`).

## Functional status (English)

- Navigation: Overview · Contacts · Agenda · Finance + profile avatar (dark mode, admin, sign out).
- Add new: the + button opens a bottom sheet titled "Agregar nuevo" with 8 actions (Contact, Task, Event, Note, Invoice, Expense, Timer and Account). Invoice opens the invoice editor (see "Invoices and quotes"); Expense opens the movement form with the expense type preselected. With no accounts yet, the account editor opens and a notice is shown. Timer only dispatches `serpix:timer-start`. The sheet closes on backdrop or Escape (and after choosing an action) and traps focus.
- CRM: contacts with a relationship (client, potential client, partner, potential partner, supplier, prospect), relationship filter, expandable card with linked tasks, events and notes. Phone suggests `+54` but accepts any number; X, Instagram, Telegram, WhatsApp and LinkedIn are optional (`@handle` or URL); free-form notes.
- Agenda: General (Overdue/Today/Upcoming), Calendar (month view with per-type dots) and List (type filter) tabs. Checklist tasks with due date and contact; events; Markdown notes with full-screen read/edit and preview.
- Upcoming (Agenda → General): chronological; red "Vencidas" (overdue) on top, each month heading shown once ("Octubre", with the year only if not current, sticky) and per-day sub-headings "Hoy · Vie 30", "Mañana · Sáb 31", "Mar 3" without repeating the month; time on the right, type icon with tooltip, "Sin fecha" at the end. "Today" is the America/Buenos_Aires day.
- Agenda with the past: General and List are one timeline with the past, today and what's next (month once + day, color per month). It opens positioned on "Hoy" (no animation, accounting for sticky headings); the earlier days are above (one month loads at a time when you reach the top, without scroll jumps) and the next ones below. Overdue pending tasks sit in a red "Vencidas" block right above Today (plus an "N vencidas" pill that jumps to them when they're off screen); past done items appear dimmed on their day. A "Hoy" button (arrow points where today is) shows when you scroll away and returns to the current day. Calendar: opens on the current month with today selected, arrows or swipe for other months and "Hoy" to come back. No-date items stay at the end. Overview is unchanged.
- Brand colors: `app/brand.css` defines the 4 tones (pink #fe4aab, cyan #39c5ff, duck yellow #f6cd35 and violet #ab96ff, the exact pink/cyan midpoint in OKLCH with chroma lowered to fit sRGB) with soft and readable-text variants (`--brand-*` tokens); it loads after `globals.css`. Selected states, the + button, borders and focus use only these tones. Month colors: `lib/palette.ts` rotates pink, cyan, yellow and violet by month (the same month always gets the same tone) and is used on month headings in Agenda, the calendar, finance movements and inquiries.
- Portfolio inquiries: the `lulox.com.ar` (/contratar) form still sends the email and also forwards the inquiry to `POST /api/inbound/portfolio` over a Service Binding (`inquiries` table; secret in `x-serpix-secret`, 401 without it; max 12 KB, 5 per hour per email and 30 per 10 min). Find them under **Contacts → Requests** (unread counter on the nav, the Overview inbox icon and the tab): read/unread, archive, reply by email (`mailto:`) and convert to contact (creates a new potential-client contact; if a contact with that email exists it is only linked, never modified).
- Push notifications: Web Push with VAPID built on WebCrypto (`lib/webpush.ts`, dependency-free; `npm test`). Enable per device in Profile → Notifications (`push_subscriptions` table). A new inquiry pushes to all your devices; tapping the notification opens it. On iPhone, add Serpix to the home screen first.
- Overview: compact first screen (one-line greeting, short date, 4 icon KPIs with tooltips that link to their section, upcoming tasks with status/date/contact icons and a complete checkbox).
- Relations: a contact can be client, partner and/or supplier at once, each potential or confirmed (`contacts.relations` JSON column; when NULL it is derived from the legacy `role` without touching rows: client/partner/supplier → confirmed, client_potential/partner_potential → potential, `potential` ("prospect") → no relation). Saving writes `relations` and keeps `role` coherent. Relation and state filters in Contacts.
- Contact photo: initials by default; pick the photo from X, Telegram, GitHub, LinkedIn or the email (Gravatar via SHA-256), or upload your own. Each is downloaded once, center-cropped to 256 px and stored as a few-KB WebP in D1 (additive columns `avatar_data`, `avatar_source`, `github_url`), served from `/api/avatar/<id>` to the owner only. Key-less sources: unavatar.io (X, Telegram, GitHub, LinkedIn; free tier ~25 lookups/day per IP) and Gravatar; Instagram requires a paid plan, so it is not offered.
- Automatic photo: if a contact has no chosen/uploaded photo, opening its card (or saving it) makes the browser try GitHub, X, Telegram, LinkedIn and the email Gravatar in order, keep the first valid image and store it (`avatar_source = auto:<network>`). It never overrides a chosen or uploaded photo. If no network has a photo, the attempt is recorded (`avatar_tried_at/key`) and not retried until the networks change or 7 days pass; the list never calls external services. unavatar.io answers 200 with a generic SVG silhouette when it cannot read a LinkedIn profile: that is discarded (not a photo). Instagram is excluded (paid on unavatar; the web API requires login).
- WhatsApp photo: with a phone saved, Serpix looks up that number's public WhatsApp photo (unavatar.io, no account or API key; neither your WhatsApp nor paid services) and adds it to the sources (WhatsApp chip and automatic order: GitHub, X, Telegram, LinkedIn, WhatsApp, email). The phone is normalized to international format (`waNumber` in `lib/avatar-client.ts`, e.g. +54 11 5555-1234 → 5491155551234). Without a public photo unavatar returns a generic silhouette: it is recognized by its hash and discarded. The number is sent to unavatar.io (~25 lookups/day per IP, shared with the other sources). Next to the phone there is a button that opens `wa.me/<number>`.
- Profile suggestions: automatic suggestions are NOT possible (no free search engine allows server-side queries: DuckDuckGo gives a captcha or 522, Brave 429, Bing returns unrelated results). Instead, next to LinkedIn and Instagram a magnifier button opens the name search (+ company on LinkedIn) in a new tab so you pick the profile and paste it.
- Money is stored in integer minor units (ARS/USD); data is isolated per user; no demo data.
- Finance: income and expense totals are SQL aggregates with no row limit ("Ver más" pages the movements list 250 at a time), the account opening balance can be edited and is saved, and data refreshes on focus, when the tab becomes visible, and after each change (no 10 s polling).
- Timer and time entries: a sheet with `HH:MM:SS` (Pause/Resume and Stop), a floating pill when minimized, and a screen to save the entry (start and end in Buenos Aires time, ±5 min, round up to 15 minutes, task, billable ARS). State lives in D1 (`timer_state`, `time_entries`) and is cached in the browser for the first paint. Agenda (General and List) shows tracked time on each task; Finance has a "Tiempo registrado" panel.
- Invoices and quotes (internal vouchers, **not fiscal ARCA invoices**; the PDF says so): `documents`, `document_items` and `document_time_entries` tables (additive migration `0010_documents.sql`). Quote or invoice with a correlative number per type and user (`P-0001`, `F-0001`), client (contact), date, due date, ARS/USD currency, items (description, quantity, price) and notes. Statuses: draft, sent, paid, void; **overdue** is not stored, it is derived (a sent, unpaid invoice whose due date is before today in Buenos Aires time). "Marcar enviada" only changes the status: Serpix sends no email. Quote → invoice in one click (copies items and client, due in 15 days; idempotent: one quote creates one invoice). "Cobrar" picks an account in the same currency and creates the Finance income (category "Factura") exactly once: the `documents.transaction_id` link is unique, repeating the action never duplicates and a paid invoice is closed. "Horas" imports the client's billable hours (tasks of that contact, not on any voucher yet) as items and flags them so they are never billed twice. Only drafts can be deleted; the rest are voided. Found in Finance (panel "Facturas y presupuestos") and under + → Factura (`app/documents.tsx`, API in `app/api/documents`, logic in `lib/documents.ts`).
- PDF and sharing: the PDF is built in the browser, with no paid service and no server (`lib/pdf.ts` is a minimal dependency-free PDF writer; `lib/document-pdf.ts` is the layout with the v5 logo and the palette; `app/document-pdf.ts` measures text with canvas). "PDF" downloads it; "Compartir" uses Web Share with the file when the device supports it and otherwise downloads the PDF and opens WhatsApp (`wa.me`) with a short message to attach it to.
- Overdue payments: overdue invoices show a red background and label in the list and in an "Cobros atrasados" panel on Overview. A free daily Cloudflare cron (`worker.ts`, 12:00 UTC = 09:00 Buenos Aires) sends ONE push per user listing the invoices that just became overdue (same VAPID mechanism as inquiries; `lib/documents-push.ts`) and marks them (`overdue_notified_on`) so it never repeats; a failed delivery is retried the next day. `worker.ts` wraps the OpenNext handler and is the Worker entry point (`main` in `wrangler.jsonc`).
